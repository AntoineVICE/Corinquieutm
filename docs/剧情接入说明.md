# Ink 剧情接入说明

这版将文案、选项和剧情条件放在 Ink 里，Godot 负责场景、人物、输入、对话显示和保存。详细对白作为本次实现依据。右侧纵向阅读形式参考《极乐迪斯科》，外观使用用户提供的羊皮纸 UI：人物名红褐色，台词深墨色，动作和物件描述褐灰色。编号选项是透明文字按钮，悬停和键盘聚焦只改变文字颜色。

## 文件关系

```text
story/day1.ink                 总入口：变量声明、INCLUDE
    ├─ dorm.ink               宿舍
    ├─ courtyard.ink          外院
    ├─ garden.ink             瓦茨拉夫、西蒙、鸡舍
    ├─ kitchen.ink            罗德里戈
    ├─ infirmary.ink          药舍／病舍
    └─ cloister_south.ink     南回廊强制剧情、安布罗斯
         ↓ 双击「编译对白.cmd」
story/day1.json                Ink 官方编译产物
         ↓ InkGD 运行库
Godot 场景 → 选择命名段落 → 右侧对话栏 → 玩家选择 → Ink 决定下一句
```

源文件使用 UTF-8。中文对白直接编辑即可；运行时读取编译后的 `story/day1.json`。旧版自定义对白 JSON 已清理，正式源稿保留在 `story/`。

## 先认识这几个记号

| 写法 | 意思 |
| --- | --- |
| `=== dorm_wakeup ===` | 一段内容的名字（Ink 称为 knot） |
| 普通一行文字 | 一次点击显示的一个段落 |
| `# speaker:扬` | 这一段的说话人；此标签是工程约定 |
| `# title:外院 · 菲利普` | 保留的作者元数据；简洁 UI 不显示此标签 |
| `# tone:description` | 整段用物件描述的褐灰色显示；工程约定 |
| `+ [选项文字]` | 可以再次出现的选项；方括号防止 Ink 自动重复打印回答 |
| `-> philipp_request` | 跳到另一段 |
| `-> END` | 结束当前交谈，回到场景 |
| `~ oats_request_known = true` | 记录剧情事实 |
| `// 注释` | 给作者看的备注，不显示给玩家 |

Ink 的 `*` 默认是一次性选项，`+` 是可再次出现的选项。本工程给可补问、可重复交互使用 `+`。HUD 会将选中的选项追加到阅读记录，所以请沿用 `+ [文字]`，避免使用会自动回显的无括号选项而把回答显示两遍。

对话用中文双引号 “ ” 包住发言。工程会将引号里的话显示为深墨色、引号外的动作显示为褐灰色，不需要另插“旁白”人物。物件描述整段加 `# tone:description`；纯动作选项加 `# tone:action`。

## 一个可以照抄的新物件段落

把下面内容加到 dorm.ink，编译后，在宿舍中创建一个 Interactable，将 Dialogue Id 填为 inspect_window：

```ink
=== inspect_window ===
# title:见习生宿舍 · 窗户
窗外传来清晨的风声。 # speaker:窗户 # tone:description
-> END
```

这段只是新增内容的示范，没有放进实际剧情，也没有替作者扩写原稿。新建交互点还需设置独立的 Interaction Id、显示名称和位置；Kind 选择 DIALOGUE。退出地点的门则使用 EXIT，配置目标地点与出生点，无需在 Ink 中写传送。

## 从你的原稿看实际写法

```ink
=== dorm_wakeup ===
# title:见习生宿舍 · 晨祷
“金德日赫？” # speaker:扬
“快起床，钟声已经响了。” # speaker:扬
“我去章会厅等你，如果你今天又迟到的话，就算是我也没有办法在院长面前替你说情了。” # speaker:扬
+ [“是...是...我马上...”]
    ~ wake_response = "spoken"
    -> wakeup_finish
+ [（沉默且疲惫地从床上爬起来） # tone:action]
    ~ wake_response = "silent"
    -> wakeup_finish

=== wakeup_finish ===
~ dorm_wakeup_done = true
-> END
```

两个回答只记录语气，最后汇合到同一处。改变一句对白，只改正文；改变选项文字，只改方括号里的文案；改变它跳到哪里，改其下方 `->` 后的段落名。

“离开”是选项标签，不是台词内容：

```ink
+ [“好的。” # action:离开]
    ~ oats_response = "accept"
    -> END
```

标签要放在方括号内部，才能在玩家尚未点击时显示。选中后回答会留在阅读记录中，末尾按 E 关闭交谈。

## 你确认的补问逻辑

```ink
=== philipp_followup ===
# title:外院 · 菲利普
{ oats_request_known:
    -> philipp_reminder
}
+ [“发生什么事了？”]
    -> philipp_request
+ [（离开） # tone:action]
    -> END
```

`oats_request_known` 初始为 false。只有实际推进到“我们没有燕麦喂马了”那段，才置为 true。第一次选择沉默离开不会自动得到口信；回来仍有询问入口。第一次直接问与后来补问共用 `philipp_request`，这段只维护一份。已知口信时跳到 `philipp_reminder`，显示“找到扬兄弟了吗？……劳烦你快一些。”。

变量声明集中在 day1.ink。Ink 原生条件、变量和访问记录都由真实运行库执行。编译启用访问次数记录，存档包含完整 Ink 状态；Godot 的 flags / decisions / observations 是从 Ink 读取的界面投影，不在两处各写一套分支。

如果只是增加由 Ink 自己判断的新变量，在 day1.ink 声明并在剧情里使用即可。如果还要让新变量控制 Godot 的门或人物显隐，需要把这个布尔变量名加入 game_state.gd 的 FLAG_IDS，世界交互才能读取它。新变量会随完整 Ink 状态保存。

当前从交谈结束点保存。对话框打开时不提供菜单保存；关闭程序后从最近的安全存档继续。新版存档为 user://story_day1_ink_v3.json。修改并编译剧本后，先停止再 F5，并从菜单重新开始；不强行把旧脚本的位置指针套在新文本结构上。

本次对上一版地图工程的精确剧本哈希提供兼容。清理测试数据前已验证“外院沉默离开”和“已知燕麦口信”两种旧存档；迁移保留原变量、位置和访问记录，新变量采用 Ink 默认值。兼容仅针对已验证的旧版与本次构建，不是放开任意存档。后续改动并编译剧本时应重新验证兼容，不要随意放宽哈希检查。

南回廊强制剧情在场景淡入后自动开启，期间锁住移动与其他交互。`IntroCamera` 定义开场镜头；即使旧存档从东端或厨房进入，也会展示安布罗斯和塞维里诺，保留主角实际入口位置。结尾恢复镜头跟随，塞维里诺隐藏，安布罗斯开放小手交互。此过程不增加地图通路。

## 接入美术与音乐

- 地点根节点：Background Texture、Foreground Texture、Music、Ambience。
- NPC 交互点根节点：Portrait Texture；这是场景全身图，当前没有对话头像框。Portrait Bounds 排除透明画布，Portrait Height 默认 343，与主角实际可见身体高度相同；脚底锚定节点坐标。Portrait Outline 可在运行时按原像素轮廓裁掉导出残留，不改写 PNG。人物前后绘制次序按脚底位置切换。
- 主角根节点：Idle Texture 为右侧 A0，Idle Texture Left 为左侧 A0；Walk Frames 已接 walk_frames.tres 中的 walk_right / walk_left，两组各六帧、8 帧／秒。按移动方向使用对应原画，不额外镜像；停止移动、进入对话或菜单时显示对应方向的 A0。
- 主角素材来自用户的「行走各帧.zip」，12 张 1440 × 2560 透明 PNG 原样保存在 assets/characters/protagonist/right 和 left 中。Art Scale = 0.26，可见人物高度约 343，以头顶低于可见门洞为最终比例基准。Idle 和 Animated 均取消 Centered，位置为 (-720, -1991)，保留各帧共同画布基准，脚底变化小于 1 个设计单位。
- 宿舍已接入用户提供的「男主的卧室.png」（3840 × 2160），工程文件为 assets/backgrounds/dorm_room.png。图像内容与原文件完全一致，Sprite 等比缩放为 1/3，显示完整的 1280 × 720 房间。
- 宿舍脚底 y = 654，与椅脚落在同一条线上，行走横向边界 145–1220，镜头右边界 1280；外院暂用原来的 1600 × 720 场景和 y = 570 地面。每个地点通过 Walk Y / Walk Left / Walk Right 单独配置。
- 宿舍交互点已对应画面上的左侧书桌、墙面十字架、床、床右侧花瓶下面的木箱、最右侧的门。Marker Offset 只移动提示位置，交互站位仍在地面。
- 已有存档的位置会按当前地点的行走边界归位，不因本次美术替换重置剧情。
- F11 / Alt+Enter 可随时切换全屏和窗口，菜单也有对应按钮。
- 插入新地点仍由 main.gd 的地点表和出口配置负责；当前已注册 12 个地点。新地点还需同步加入 game_state.gd 的 LOCATION_IDS / LOCATION_WIDTHS，并配置双向出口及各自的返回 Marker2D。

## 新 UI 的显示与交互

- 三张用户 PNG 原样保存在 assets/ui：dialogue_sidebar.png、exploration_frame.png、interaction_prompt.png。原图透明区域保留，通过 AtlasTexture 引用有效画面，未改写源图。
- 探索边框铺满 16:9 内容画面，鼠标事件穿透。画面上没有场景名、时间、目标、说明条、日志按钮或菜单按钮；日志与菜单仍可主动按 J／Esc 打开。
- 可交互物件始终显示约 36 × 36 的小手形图标，靠近和悬停均不展开、不改变大小。走近后直接点击该小手或按 E 打开对白。每个小手有独立的点击目标；鼠标可以选择范围内任一物件，E 使用最近的物件，二者都检查距离与剧情条件。
- 对话纸张为 480 × 664 个设计单位，右侧停靠；内容区域距离纸张左侧 76、右侧 40、上方 138、底部 40 个设计单位，为左侧花纹、顶部装饰与正文留出清楚的间距。进入用 0.34 秒滑入，结束用 0.24 秒滑出。两段动画期间锁定移动和对话输入，避免重复结束或误跳段落。
- 全部回答选项和“继续／结束”均使用 StyleBoxEmpty，所有状态没有填充或边框；只有文字颜色发生变化。可鼠标点击，也保留数字键选择、E／空格推进。
- 正文使用 18 号宋体、8 个设计单位的额外行距，人名以 16 号红褐色单独成行；正文与叙述分别为深墨和褐灰色。长对白保留滚轮翻阅，滚动条完全透明且不接受鼠标点击；选项在下方独立排列，所有状态保持透明。
- 布局在 ui/hud.tscn，文字样式在 ui/dialogue_theme.tres，滑动动画在 scripts/hud.gd。改纸张宽度时须同步调整 _set_slide_progress() 的左右偏移值。
- UI 保留既定排版：不添加时间、地点标题或展开的交互横条；新对白沿用透明文字选项与“结束”。

## 可走范围与遮挡

`Walk Polygon` 表示脚底可走区域；空数组保留原来的横向行走。菜园、章会厅、厨房和病舍有浅纵深，人物始终保持当前地点固定比例。`Walk Obstacles` 排除其中实物占地，角色分小步检查并沿边缘滑动，不能直接穿过桶、石块或树桩。读档若落在新增障碍内，会就近归位到可走地面。

餐厅前排桌子使用 Polygon2D 引用原画纹理并按轮廓覆盖人物。菜园鹅和鸡同样引用原始全景纹理，挂 `scripts/scenery_occluder.gd`，由 `depth_y` 指定落脚深度：人物脚底在其后方时，动物绘制在人物前面；反之放到人物后方。修改轮廓时须保持 UV 与背景显示比例一致。没有覆盖或重绘原画。

转场由 HUD 的 Fade 控件处理：旧画面 0.28 秒淡出，在全遮盖帧加载新地点、安排人物与镜头，再用 0.42 秒淡入。探索装饰边框位于 Fade 之上；动画期间禁用移动、出口与背景点击。

`ui/character_clarity.gdshader` 对行走源帧的偏软线条做轻度补偿，未修改 PNG；A0 不应用补偿，其余帧强度 0.55。可在 `scripts/player.gd` 的 `_update_walk_clarity` 中调整。
